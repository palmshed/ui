Migration guide

Moving from inline CSS to palmshed/ui.

Step 1: Link the CSS files

Add the palmshed/ui stylesheets to your page <head>:

<link rel="stylesheet" href="../css/tokens.css">
<link rel="stylesheet" href="../css/base.css">
<link rel="stylesheet" href="../css/layout.css">
<link rel="stylesheet" href="../css/typography.css">
<link rel="stylesheet" href="../css/components.css">

Only include what you need. If you don't use tables, skip typography.css. If you don't use cards, skip components.css.

Step 2: Replace inline styles with tokens

Replace hardcoded color values with CSS custom properties:

/* Before */
body { background: #080909; color: #e1e2e2; }

/* After */
body { background: var(--bg); color: var(--text); }

Step 3: Use semantic HTML

Replace generic containers with the palmshed/ui layout structure:

<nav>...</nav>
<div class="hero">...</div>
<div class="page">...</div>
<footer>...</footer>

Step 4: Replace custom components

Replace your own button, card, and badge styles with the palmshed/ui classes:

Your custom classpalmshed/ui replacement
.btn.button
.project-card.card
.status-label.badge or .tag
.notice.alert.alert-info
.form-input.input

Step 5: Remove inline

After migration, remove any <style> blocks that duplicate palmshed/ui styles. Use tokens for any remaining custom styles.

Step 6: Verify

  • All pages render without visual regressions.
  • Focus states are visible when tabbing.
  • Mobile menu works (if using nav template).
  • Color contrast meets accessibility requirements.
