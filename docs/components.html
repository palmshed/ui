Components

Every component in palmshed/ui with live previews, variants, and accessibility notes.

Button

Use for links and actions. Applies consistent sizing, border, and hover state.

Primary Secondary
Default Default 
<a href="/signup" class="button">Get Started</a>

<button type="button" class="button">Submit</button>

Accessibility

  • Keyboard accessible by default (native <button> or <a>).
  • Visible focus state via :focus-visible in base styles.
  • Minimum touch target is approximately 34px.

Do's

  • Use <a class="button"> for navigation, <button class="button"> for actions.
  • Keep button labels short and action-oriented.

Don'ts

  • Don't use <div> or <span> as buttons.
  • Don't remove focus outlines.

Card

Use for summarizing projects, linking to content, or grouping related information.

Project name
Short description of the project and what it does.
 
<div class="card">
  <a href="/project">
    <div class="card-name">Project name</div>
    <div class="card-desc">Short description.</div>
  </a>
</div>

Variants

Cards have one variant: linked (wrapping anchor) or static (no anchor).

Accessibility

  • When using a linked card, the anchor provides the interactive target.
  • Do not nest interactive elements inside a linked card.

Do's

  • Keep card names concise (1-3 words).
  • Use card descriptions as secondary text.

Don'ts

  • Don't put interactive elements (buttons, links) inside a linked card.
  • Don't use cards for data tables or long-form content.

Badge

Use for status indicators, version labels, or metadata.

stable alpha v1.0.0 
<span class="badge">stable</span>

Accessibility

  • Badges are decorative by default. If the badge conveys information not present in surrounding text, use aria-label or visually hidden text.

Do's

  • Use short labels (1-2 words).

Don'ts

  • Don't use badges for interactive elements.
  • Don't use badges as the sole indicator of status - pair with text when critical.

Tag

Use for labels, categories, or taxonomy terms. Similar to badges but uppercase with distinct styling.

css html design 
<span class="tag">css</span>

Accessibility

  • Same guidance as badges - tags are decorative; pair with text if the label is essential.

Do's

  • Use single words.

Don'ts

  • Don't use tags for interactive filtering without proper ARIA roles.

Alert

Use for status messages, notices, or warnings.

This is an informational message.
This is a note with accent border.
<div class="alert alert-info">
  This is an informational message.
</div>

Variants

ClassUse
.alert-infoGeneral information (default, one variant currently)

Accessibility

  • For critical alerts, add role="alert" to notify assistive technology.
  • For status updates that don't require immediate attention, use role="status".

Do's

  • Keep alert text brief and actionable.

Don'ts

  • Don't use alerts for permanent page content - use cards instead.

Input

Use for text-based form inputs. Includes focus styling via :focus.

<input type="text" class="input" placeholder="Enter your email">

Accessibility

  • Always pair inputs with a <label>.
  • Focus state uses accent border color for visibility.

Do's

  • Use semantic <label> elements associated via for attribute.
  • Use appropriate type attributes (email, url, search, etc.).

Don'ts

  • Don't use placeholder as a substitute for labels.

Code block

Use for multi-line code examples. The .code-block class mirrors the <pre> styling.

.example {
color: var(--accent);
}
<div class="code-block">
  .example {
    color: var(--accent);
  }
</div>
